# API Contracts - Auth Service

## General

- base path: `/api/v1`
- headers on every request (400 `MISSING_CLIENT_HEADERS` if missing, used for action_logs):
    - `X-Platform` (android / ios)
    - `X-Device-Model`
    - `X-App-Version`
    - `X-Device-Id` (uuid generated by the app on first launch)
- protected routes: `Authorization: Bearer <access_token>`
- access token: JWT, 15 min
- refresh token: random string, 30 days, rotated on each refresh, stored in keystore/keychain
- error format:
    ```json
    { "error": { "code": "EMAIL_NOT_VERIFIED", "message": "..." } }
    ```
    app checks `code`, not `message`
- common errors on all routes: 400 `VALIDATION_ERROR`, 429 `RATE_LIMITED` (+ `Retry-After`), 500 `INTERNAL_ERROR`
- password: 8–128 chars (max length so nobody sends huge passwords to slow down hashing)

## Public

- auth/register
    - Method: POST
    - Request Body:
        - email (string)
        - password (string)
        - display_name (string) -- needed, profiles.display_name is NOT NULL
    - Response Body:
        - user_id (uuid)
    - Status Codes:
        - 201: Created
        - 409: EMAIL_TAKEN
    - Notes:
        - creates users + profiles row in one transaction, sends verification mail
        - 409 does show the email exists, we accept it (matches the flow), rate limited

- auth/login
    - Method: POST
    - Request Body:
        - email (string)
        - password (string)
    - Response Body:
        - access_token (string)
        - refresh_token (string)
        - expires_in (int, seconds)
    - Status Codes:
        - 200: OK
        - 401: INVALID_CREDENTIALS -- same response for wrong email or wrong password
        - 403: EMAIL_NOT_VERIFIED -- only after password is correct
        - 429: ACCOUNT_LOCKED -- counted per email typed, works even if email doesn't exist
    - Notes:
        - if email doesn't exist, still hash-compare against a dummy hash (same response time)
        - saves login_attempts row, upserts device, starts new refresh token family

- auth/refresh
    - Method: POST
    - Request Body:
        - refresh_token (string)
    - Response Body:
        - access_token (string)
        - refresh_token (string) -- NEW one, old one gets revoked
        - expires_in (int)
    - Status Codes:
        - 200: OK
        - 401: INVALID_REFRESH_TOKEN
    - Notes:
        - old (already rotated) token used again = stolen -> revoke whole family
        - app side: only one refresh request at a time, other requests wait for it.
          two parallel refreshes with the same token look like theft and log the user out

- auth/logout
    - Method: POST
    - Request Body:
        - refresh_token (string)
    - Response Body: (empty)
    - Status Codes:
        - 204: always, even if token is already revoked/unknown
    - Notes:
        - revokes the token family

- auth/password-reset
    - Method: POST
    - Request Body:
        - email (string)
    - Response Body: (empty)
    - Status Codes:
        - 202: always (account exists or not, limit reached or not)
        - 429: per IP only, never per email (would leak that the account exists)

- auth/password-reset/confirm
    - Method: POST
    - Request Body:
        - token (string)
        - new_password (string)
    - Response Body: (empty)
    - Status Codes:
        - 204: OK
        - 400: TOKEN_INVALID (unknown or used)
        - 400: TOKEN_EXPIRED
    - Notes:
        - consume token, save new hash, revoke ALL refresh tokens of the user
        - set email_verified_at if null (clicking the link proves the email)

- auth/email-verification
    - resend verification mail
    - Method: POST
    - Request Body:
        - email (string)
    - Response Body: (empty)
    - Status Codes:
        - 202: always
        - 429: per IP only

- auth/email-verification/confirm
    - Method: POST
    - Request Body:
        - token (string)
    - Response Body: (empty)
    - Status Codes:
        - 204: OK
        - 400: TOKEN_INVALID
        - 400: TOKEN_EXPIRED
    - Notes:
        - mail link: `https://<domain>/verify?token=...` as android app link -> opens app, app sends the POST
        - no app installed -> small web page with a confirm button (POST)
        - never consume the token on GET, mail scanners open links automatically. same for reset links

- auth/oauth/{provider}
    - provider: google | facebook
    - Method: POST
    - Request Body:
        - token (string) -- google: id token, facebook: access token. verified server side
    - Response Body:
        - access_token (string)
        - refresh_token (string)
        - expires_in (int)
        - is_new_user (bool) -- true -> app goes to profile setup
    - Status Codes:
        - 200: OK
        - 401: OAUTH_INVALID
        - 409: LINK_REQUIRED -- account exists with this email but provider email not verified. login with password then link from settings
        - 422: OAUTH_EMAIL_MISSING -- no email from provider (fb accounts made with phone number)
    - Notes:
        - verified email matches an account -> link + login
        - no match -> create account, email_verified_at = now

## Protected

- auth/me
    - Method: GET
    - Response Body:
        - user_id (uuid)
        - email (string)
        - email_verified (bool)
        - has_password (bool)
        - linked_providers (string[])
    - Status Codes:
        - 200: OK
    - Notes:
        - settings screen uses it for link/unlink buttons

- auth/oauth/{provider}/link
    - Method: POST
    - Request Body:
        - token (string)
    - Response Body: (empty)
    - Status Codes:
        - 204: OK
        - 401: OAUTH_INVALID
        - 409: PROVIDER_IDENTITY_IN_USE -- this google/fb account is linked to another user
        - 409: PROVIDER_ALREADY_LINKED -- this user already has this provider
    - Notes:
        - emails don't have to match, user is already logged in

- auth/oauth/{provider}
    - Method: DELETE
    - Response Body: (empty)
    - Status Codes:
        - 204: OK
        - 404: NOT_LINKED
        - 409: LAST_LOGIN_METHOD -- no password + only provider, unlinking would lock the account

- auth/logout-all
    - Method: POST
    - Response Body: (empty)
    - Status Codes:
        - 204: OK
    - Notes:
        - revokes all refresh tokens. access tokens still work until they expire (15 min max), that's the JWT tradeoff

## Rate limits

| route | per IP | per account/email |
|---|---|---|
| login | 100 / 15 min | 5 fails / 15 min -> locked 15 min |
| register | 30 / hour | - |
| password-reset | 30 / hour | 3 mails / hour (silent, still 202) |
| email-verification | 30 / hour | 3 mails / hour (silent, still 202) |
| refresh | 120 / min | - |

per IP is loose on purpose: at a party everyone is on the same wifi = same IP, and mobile carriers share IPs too. per account limit is what actually stops bruteforce.
numbers to adjust after load testing.

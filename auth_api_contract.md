# API Contracts - Auth Service

## General

- base path: `/api/v1`
- ✅ = implemented; 🟡 = implemented but live verification is pending; unmarked routes are planned or unfinished.
- OAuth supports Google only. Login and linking use browser sessions with intent bound to each OAuth state; complete each attempt in the same browser session.
- headers required on non-OAuth auth requests (400 `MISSING_CLIENT_HEADERS` if missing):
    - `X-Platform` (android / ios)
    - `X-Device-Model`
    - `X-App-Version`
    - `X-Device-Id` (uuid generated by the app on first launch)
- protected routes: `Authorization: Bearer <access_token>`
- Google OAuth start/callback require no device headers or access token; use the same browser and its OAuth session cookie throughout.
- access token: JWT, duration configured by `ACCESS_TOKEN_EXPIRES_IN`
- refresh token: signed JWT, duration configured by `REFRESH_TOKEN_EXPIRES_IN`, rotated on each refresh, stored in keystore/keychain
- error format:
    ```json
    { "error": { "code": "EMAIL_NOT_VERIFIED", "message": "..." } }
    ```
    app checks `code`, not `message`
- common errors on all routes: 400 `VALIDATION_ERROR`, 429 `RATE_LIMITED` (+ `Retry-After`), 500 `INTERNAL_ERROR`
- password: 8–128 chars (max length so nobody sends huge passwords to slow down hashing)

## Public

- ✅ auth/register
    - Method: POST
    - Request Body:
        - email (string)
        - password (string)
        - display_name (string) -- needed, profiles.display_name is NOT NULL
    - Response Body:
        - user_id (uuid)
    - Status Codes:
        - 201: Created
        - 409: EMAIL_TAKEN
    - Notes:
        - creates users + profiles row in one transaction, sends verification mail
        - 409 does show the email exists, we accept it (matches the flow), rate limited

- ✅ auth/login
    - Method: POST
    - Request Body:
        - email (string)
        - password (string)
    - Response Body:
        - access_token (string)
        - refresh_token (string)
        - expires_in (int, seconds)
    - Status Codes:
        - 200: OK
        - 401: INVALID_CREDENTIALS -- same response for wrong email or wrong password
        - 403: EMAIL_NOT_VERIFIED -- only after password is correct
        - 429: ACCOUNT_LOCKED -- five failed password attempts for an existing account within 15 minutes
    - Notes:
        - unknown users and Google-only users without a password use a dummy hash comparison before INVALID_CREDENTIALS
        - stores failure counters on the user; starts a new refresh token family using the supplied device ID

- ✅ auth/refresh
    - Method: POST
    - Request Body:
        - refresh_token (string)
    - Response Body:
        - access_token (string)
        - refresh_token (string) -- new token; the previous token is marked used
        - expires_in (int)
    - Status Codes:
        - 200: OK
        - 401: INVALID_REFRESH_TOKEN
    - Notes:
        - each login creates a separate family; devices and repeated logins stay independent
        - token IDs and hashes remain stored after rotation; old records have `used_at` set
        - old (already rotated), unexpired token used again = stolen -> revoke whole family
        - app side: only one refresh request at a time, other requests wait for it.
          two parallel refreshes with the same token look like theft and log the user out

- ✅ auth/logout
    - Method: POST
    - Request Body:
        - refresh_token (string)
    - Response Body: (empty)
    - Status Codes:
        - 204: always, even if token is already revoked/unknown
    - Notes:
        - revokes only the supplied token’s family; a still-valid rotated token can identify that family
        - no access token required; invalid, expired, unknown, or already-revoked refresh tokens are no-ops
        - existing access tokens remain usable until expiry

- ✅ auth/password-reset/request
    - Method: POST
    - Authentication: no access token required; standard client headers required
    - Request Body:
        - email (required, valid email string)
    - Response Body: (empty)
    - Status Codes:
        - 202: same response for eligible, unknown or ineligible accounts, suppressed resend, and delivery/storage failures
        - 400: VALIDATION_ERROR -- invalid request fields
        - 429: RATE_LIMITED -- per-IP request limit exceeded
    - Notes:
        - eligible accounts have a verified email and an existing password; Google-only accounts are skipped
        - emails a random six-digit OTP, like email verification; stores only its password-hasher hash
        - OTP lifetime uses `OTP_LIFETIME_MS`, the same setting as email verification
        - suppresses resend while a sent token is active; replacement tokens invalidate earlier recovery tokens
        - does not disclose the token or account state in the response

- ✅ auth/password-reset/confirm
    - Method: POST
    - Authentication: recovery token in the body; no access token required
    - Request Body:
        - email (required, valid email string)
        - token (required string, exactly six digits from the recovery email)
        - new_password (required string, 8–128 characters)
    - Response Body: (empty)
    - Status Codes:
        - 204: password recovered and live refresh sessions revoked
        - 400: VALIDATION_ERROR -- invalid request fields
        - 400: TOKEN_INVALID -- unknown, already consumed, wrong-purpose token or ineligible account
        - 400: TOKEN_EXPIRED -- recovery token has expired
        - 400: TOKEN_ATTEMPTS_EXCEEDED -- `MAX_TOKEN_ATTEMPTS` reached
    - Notes:
        - locks the user by email and looks up the latest recovery token once; validates expiry, single-use state and `MAX_TOKEN_ATTEMPTS`
        - consumes all outstanding recovery tokens, updates the password hash, clears login failures/locks and revokes all live refresh families in one transaction
        - failed writes roll back the entire recovery; tokens can only be successfully consumed once
        - existing access tokens remain usable until expiry; sign in again for new refresh credentials
        - incorrect OTP guesses count toward the attempt limit even when rejected
        - email verification tokens cannot be used for password recovery
- ✅ auth/email-verification
    - resend verification mail
    - Method: POST
    - Request Body:
        - email (string)
    - Response Body: (empty)
    - Status Codes:
        - 202: always
        - 429: per IP only

- ✅ auth/email-verification/confirm
    - Method: POST
    - Request Body:
        - email (string)
        - token (string, exactly 6 digits)
    - Response Body: (empty)
    - Status Codes:
        - 204: OK
        - 400: TOKEN_INVALID (unknown email, unknown/used token, or incorrect code)
        - 400: TOKEN_EXPIRED
        - 400: TOKEN_ATTEMPTS_EXCEEDED
    - Notes:
        - mail contains a 6-digit OTP; the app submits the email and code in the POST body
        - code expires after 5 minutes; at most 5 attempts per code, including incorrect guesses
        - expired/used tokens are rejected before reserving an attempt; OTP comparison follows the conditional attempt update
        - successful confirmation consumes the token and verifies the email

- ✅ auth/oauth/google
    - Method: GET
    - Request Body: none
    - Response Body: none; redirects the browser to Google
    - Status Codes:
        - 302: redirect to Google sign-in/consent
    - Notes:
        - open in a browser; do not send a Google token in the request body
        - creates a ten-minute OAuth state session using the `music-room.oauth` cookie
        - retain the cookie and use the same host throughout the flow

- ✅ auth/oauth/google/callback
    - Method: GET
    - Request Body: none
    - Query Parameters (supplied by Google):
        - code (string) -- authorization code on success
        - state (string) -- must match the initiating browser session; consumed once
        - error (string, on denial/failure instead of code)
    - Response Body:
        - for linking: `{ "message": "Google account linked successfully" }`; no login tokens are issued
        - for normal Google login:
        - access_token (string)
        - refresh_token (string)
        - expires_in (int)
        - is_new_user (bool) -- true -> app goes to profile setup
    - Status Codes:
        - 200: OK
        - 401: OAUTH_INVALID
        - 409: LINK_REQUIRED -- email already belongs to an account without this Google identity; authenticated linking is required
        - 409: PROVIDER_IDENTITY_IN_USE -- linking identity belongs to another app user
        - 409: PROVIDER_ALREADY_LINKED -- app user already has a Google identity
        - 422: OAUTH_EMAIL_MISSING -- Google profile has no email address
    - Notes:
        - GOOGLE_REDIRECT_URI and Google Console's authorized redirect URI must match this callback URL exactly
        - state/session failures, invalid identity and unverified Google email return OAUTH_INVALID
        - returning users are identified by the stable Google user ID, not their email
        - no automatic linking by matching email
        - new users get a null password, verified email, profile, and google_accounts row
        - account creation commits before the controller creates a refresh family and issues application JWTs
        - browser OAuth sessions have a null device ID
        - state sessions currently use memory storage; a restart clears pending attempts
        - OAuth account, callback and browser-state contract tests pass; same-browser authentication was verified during development

## Protected

- ✅ auth/me
    - Method: GET
    - Request Body: none
    - Response Body:
        - user_id (uuid)
        - email (string)
        - email_verified (bool)
        - has_password (bool)
        - linked_providers (string[])
    - Status Codes:
        - 200: OK
    - Notes:
        - settings screen uses it for link/unlink buttons

- ✅ auth/oauth/google/link
    - Method: POST
    - Authentication: app access token in `Authorization: Bearer <access_token>`
    - Request Body: none
    - Response Body: none; redirects the browser to Google
    - Status Codes:
        - 302: redirect to Google sign-in/consent
        - 401: INVALID_CREDENTIALS -- missing, invalid or expired app access token
    - Notes:
        - emails don't have to match, user is already logged in
        - saves the authenticated app user ID with this attempt's OAuth state
        - finish in the same browser session at `auth/oauth/google/callback`; linking success and conflicts are returned there

- auth/oauth/google
    - Status: planned; no controller implementation yet
    - Method: DELETE
    - Request Body: none
    - Response Body: (empty)
    - Status Codes:
        - 204: OK
        - 404: NOT_LINKED
        - 409: LAST_LOGIN_METHOD -- no password + only provider, unlinking would lock the account

- ✅ auth/logout-all
    - Method: POST
    - Request Body: none; body user IDs and refresh tokens are ignored
    - Response Body: (empty)
    - Status Codes:
        - 204: OK
    - Notes:
        - derives the user ID from the validated access JWT, not the body or device ID
        - revokes every refresh family belonging to that user, across all devices
        - existing access tokens continue working until their configured expiry

- ✅ auth/delete
    - Method: DELETE
    - Request Body: none; the account ID comes from the validated access JWT
    - Response Body: empty
    - Status Codes:
        - 200: account deleted
        - 401: INVALID_CREDENTIALS -- missing, invalid or expired access token, or deleted account
        - 409: DATA_CONFLICT -- no account was deleted

## Rate limits

| route | per IP | per account/email |
|---|---|---|
| login | 100 / 15 min | 5 fails / 15 min -> locked 15 min |
| register | 30 / hour | - |
| password-reset/request | 30 / hour | suppresses resend while a sent recovery token remains active |
| password-reset/confirm | 30 / hour | single-use recovery token |
| email-verification | 30 / hour | skips resend while the latest sent OTP remains active |
| refresh | 120 / min | - |
| logout, logout-all, me, delete | 30 / hour | - |
| Google OAuth start/callback | 30 / hour | - |

per IP is loose on purpose: at a party everyone is on the same wifi = same IP, and mobile carriers share IPs too. per account limit is what actually stops bruteforce.
numbers to adjust after load testing.
